## 🎯 Core Objectives

> In Week 2, the focus shifted to the low-level details of how data is stored and manipulated in memory. I moved beyond the basics to understand the mechanics of arrays and strings.

* **Debugging Tools & Techniques**: Mastered the art of debugging using `printf` to inspect states, the `debug50` visual debugger to step through code, and the "rubber duck" methodology to articulate and isolate logic errors.
* **Compiling & Memory**: Explored the four stages of compilation—preprocessing, compiling, assembling, and linking—and visualized how data types like `int` (4 bytes) and `char` (1 byte) are physically stored in memory.
* **Arrays & Strings**: Deepened understanding of data structures by creating arrays (contiguous blocks of memory) and treating strings as arrays of characters terminated by a `NUL` (`\0`) character.

## 🛠️ Problem Sets & Labs

> This week included several hands-on challenges to apply the concepts of arrays, cryptography, and text analysis.

* **Caesar**: Implement a program that encrypts messages using Caesar's cipher, shifting characters by a key provided as a command-line argument.
* **Readability**: Create a program that computes the approximate grade level needed to comprehend some text using the Coleman-Liau index.
* **Scrabble**: Determine which of two Scrabble words is worth more points based on a standard point value system.
* **Substitution**: Write a program that implements a substitution cipher, where the key is a permutation of the 26 letters of the alphabet.
